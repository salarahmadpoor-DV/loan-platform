# i18n rules

## Defaults

- Active locale: **fa-IR** (Persian, RTL).
- Parallel catalog: **en-US** (same keys, not auto-selected).
- `index.html` / `applyDocumentLocale` set `lang` and `dir`.
- MUI theme: `direction: rtl` and `faIR`.

## `t(key)`

Every user-visible string in components goes through `t()` from `src/shared/i18n`.

```ts
t("deal.list.title")
t("review.form.rating")
t("deal.requestRef", { id: deal.requestId })
```

Interpolation uses `{name}` placeholders in the catalog, replaced by `t(key, vars)`.

## Adding copy

1. Add the key to `src/shared/i18n/keys.ts` (`messageKeys` array).
2. Add **both** `locales/fa-IR.ts` and `locales/en-US.ts` (TypeScript `Record<MessageKey, string>` will fail the build if one is missing).
3. Use the key in the component. Do not hardcode Persian or English in JSX.

## Do not

- Detect language from IP or `navigator.language`.
- Ship a Persian-only architecture (keys stay locale-agnostic).
- Invent a third catalog until product asks for a settings switch.
- Rely on backend FluentValidation English strings as the only UX; still show them via `ErrorAlert` when they are the live ProblemDetails text.

## Future locale switch

A later settings control may call `applyDocumentLocale` and recreate the MUI theme for LTR. Until then, `DEFAULT_LOCALE` remains `fa-IR`.
